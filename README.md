# 주차장 관리 시스템

소프트웨어공학 2인 팀 프로젝트. 김원섭은 Java 데스크톱 프론트엔드를, 전승표는 차량·요금 규칙과 백엔드를 담당합니다.

[프로젝트 제안서](PROJECT_PROPOSAL.md) · [작업 명세서](SOFTWARE_REQUIREMENTS_SPECIFICATION.md) · [작업 명세서 이슈 #3](https://github.com/SWPJTeam/SW_project/issues/3)

## 프론트엔드 실행

JDK 21, Maven 3.9 이상, 그래픽 데스크톱 환경이 필요합니다. 실제 입·출차를 하려면 작업 명세서의 HTTP API를 제공하는 백엔드가 실행 중이어야 합니다.

저장소 루트에서 아래 명령을 실행합니다.

```sh
mvn -f frontend/pom.xml verify
mvn -f frontend/pom.xml compile exec:java
```

기본 서버 주소는 `http://localhost:8080`입니다. 서버 주소를 바꾸려면 환경 변수 `PARKING_API_URL`을 설정하거나 실행 인수를 전달합니다. 실행 인수가 우선합니다.

```sh
mvn -f frontend/pom.xml compile exec:java -Dexec.args=http://localhost:8081
```

## 사용 방법

- **일반 사용자 → 입·출차**에서 차량 번호와 차종을 입력해 입차를 등록합니다. 배정 면과 기록 ID를 확인한 뒤 같은 차량 번호로 출차를 정산합니다.
- **일반 사용자 → 영수증**에서 기록 ID로 정산 내역을 다시 확인합니다. 같은 실행 중 입·출차를 완료하면 최근 기록 ID가 자동 입력됩니다.
- **일반 사용자 → 정기권**에서 차량 번호와 시작일·종료일을 `YYYY-MM-DD` 형식으로 입력합니다.
- **관리자 → 구역 현황**에서 구역별 수용량과 면별 점유 상태를 확인합니다. **주차 차량**에서는 차량 번호 일부와 최소 주차 시간(분)을 조합해 조회합니다.
- **관리자 → 이용 내역**에서 출차일 범위를 지정합니다. 차량 번호로 범위를 좁힐 수 있으며, 조회한 기록과 일별 요금 합계가 함께 표시됩니다.

## 코드 구조와 API 설계

| 구성 | 책임과 설계 이유 |
| --- | --- |
| `ParkingApp` | Swing 화면과 결과 표시를 담당합니다. `SwingWorker`가 네트워크 요청을 처리해 화면이 멈추지 않도록 하고, 응답을 기다리는 동안 요청 버튼을 비활성화해 중복 클릭을 막습니다. |
| `Input` | 차량 번호 정규화와 날짜·검색 입력 검증을 담당합니다. 구역 점유, 정기권 중복, 요금 정책은 백엔드가 판단합니다. |
| `ParkingApi` | UI 동작을 HTTP 요청과 연결합니다. `enter`, `exit`, `receipt`, `registerPass`, `zones`, `active`, `history`가 화면 기능과 일대일로 대응합니다. |
| `ParkingData` | JSON 요청·응답 필드를 Java 레코드로 정의합니다. 차종 코드와 화면 표시명을 분리해 서버는 `EV`를 받고 화면에는 ‘전기차’가 표시됩니다. |

입차·출차·정기권 등록은 상태를 변경하므로 `POST`, 현황·영수증·검색 조회는 `GET`을 사용합니다. 출차 직후와 영수증 재조회에 동일한 `{session, receipt}` 구조를 사용해 같은 화면 표시 함수를 공유합니다. 서버가 반환한 정산액을 그대로 표시하므로 과거 영수증 금액이 프론트엔드의 규칙 변경으로 달라지지 않습니다.

## 검증 및 데모

`mvn verify`는 입력 검증과 로컬 HTTP 테스트 서버를 사용한 프론트엔드 계약 테스트를 실행합니다. 백엔드와 연결한 뒤에는 전기차 입차로 배정 면 확인 → 관리자 현황 조회 → 중복 입차 오류 확인 → 출차 정산 → 영수증 재조회 → 관리자 일별 합계 조회 순서로 시연할 수 있습니다.
